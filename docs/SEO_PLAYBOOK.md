# SEO playbook

The repository is the acquisition layer; the website is the product. This is how
traffic is supposed to arrive, in priority order, and how we measure whether it
is working.

## 1. Target keywords and the page that owns them

| Keyword | Intent | Owning page | Status |
|---|---|---|---|
| free AI agent tools | High, commercial investigation | `/` | Landing title |
| free LLM API | High, informational | `/llm-apis` | 63 entries + 150-word intro |
| free AI APIs 2026 | Medium | `/llm-apis` | Title + H2 |
| MCP servers list | High | `/mcp-servers` | 62 entries with install commands |
| awesome MCP servers | Medium | `/mcp-servers` | Cross-linked from README |
| free Gemini API limits | Long-tail, high intent | `/llm-apis#google-gemini` | Anchor with decoded limits |
| GitHub MCP server install | Long-tail | `/mcp-servers#github-mcp` | Copy-paste install block |
| free Cursor alternative | Medium, competitive | `/agent-tools` | Comparison framing in intro |
| free postgres hosting | Medium | `/free-tiers#supabase` | Anchor |
| free vector database | Medium | `/free-tiers#qdrant-cloud` | Anchor |

Rule for every page: one primary keyword in `<title>`, `<h1>`, the first 100
words, and one subheading. No keyword stuffing — the entries themselves are the
content, and duplicated anchors are what actually rank.

## 2. Why there are no per-resource pages in MVP

Thin pages (200 words of vendor copy plus a link) are the most common way
directories get penalised. Instead:

- Category pages carry 150+ words of **unique** intro copy, plus dozens of entries
  with original descriptions — genuine content density
- Each resource gets a stable anchor (`/llm-apis#google-gemini`) which still ranks
  for long-tail queries because of the surrounding page authority
- Link equity consolidates on 4-5 strong pages instead of being diluted over 235

Revisit at V2 when there are 600+ entries and enough unique per-entry content
(verification history, limit changes over time) to justify real pages.

## 3. Technical checklist

Every item is enforced by the build, not by discipline:

| Requirement | Implementation |
|---|---|
| Unique title + meta description per page | Next.js `metadata` export in each route |
| Canonical URLs | `alternates.canonical` per route, absolute |
| `sitemap.xml` | `app/sitemap.ts`, generated at build from data |
| `robots.txt` | `app/robots.ts`, allows all, points at sitemap |
| JSON-LD `ItemList` + `Organization` | `lib/schema.ts`, injected per category page |
| OpenGraph + Twitter cards | `app/opengraph-image` per category (V1) |
| No client-only content | Static export; every entry is in the HTML |
| Internal linking | Every category page links to ≥3 others (footer + related block) |
| 301s for renamed slugs | `next.config.js` `redirects` — slugs are permanent |
| `/llms.txt` | Generated by `scripts/export_json.py` |
| LCP < 2.0s on 4G | No hero images, system fonts, <150KB JS |
| Lighthouse ≥95 ×4 | Checked manually pre-launch, then per release |

## 4. Backlinks

1. **Reciprocal badge.** Every listed project can embed
   `https://devanimecx.github.io/free-ai-agent-stack/badge.svg`, which links back. This is the
   highest-yield, lowest-effort link source, and it scales with the catalogue
2. **Awesome lists.** Submit to `awesome-ai-agents`, `awesome-mcp-servers`,
   `awesome-llm`, `awesome-free-apis`, `awesome-selfhosted` and the
   `awesome-*` dev-tools collections. One PR each, honest description, no spam
3. **Guest posts.** dev.to / Hashnode / Medium, each with a data angle that only
   this dataset can support ("we checked 63 free LLM tiers so you don't have to")
4. **Product Hunt** in week 2 with the website as the product, not the repo
5. **Show HN** on launch day — the hook is the automated verification, not the list
6. **Vendor outreach** in week 3: ask listed vendors to link the entry from their
   own docs or community page, in exchange for the badge

## 5. Content that compounds

Beyond the four category pages:

- **"State of free AI, 2026"** — an annual data post built entirely from `git log`
  and the dataset: how many free tiers appeared, how many died, which categories
  shrank. Nobody else can write this because nobody else tracks it
- **Change log posts** — every deprecation is a small news item ("Cerebras removed
  its free tier — here are 4 replacements")
- **Comparison pages in V1** (`/compare`) — "Gemini free tier vs Groq free tier"
  is a real query with real volume

## 6. Measurement

| Metric | Source | Review cadence |
|---|---|---|
| Organic clicks, impressions, average position | Search Console | Weekly |
| Top landing pages and queries | Search Console | Weekly |
| Referring domains | Search Console / Ahrefs free | Monthly |
| Star velocity | star-history embed | Weekly |
| Website MAU | self-hosted Umami | Weekly |
| Link freshness % | `scripts/verify_links.py` summary | Daily (automated) |

Guardrails from the PRD are wired into CI, not into a spreadsheet: link rot must
stay under 5% (the verifier warns past it), page weight under 150KB JS, and build
time under 3 minutes.

## 7. Things we refuse to do

- Buy links, use PBNs, or trade "you link me, I'll rank you" schemes
- Auto-generate per-provider pages from templates
- Stuff "free AI API 2026" into every description field
- Add interstitials, newsletter popups or exit-intent modals — the whole pitch is
  that this is the non-annoying reference
